College Viva Questions & DBMS Explanation Guide

  • 1NF: Every column contains atomic (indivisible) values. Seats and tickets are not stored as comma-separated strings inside a single booking column; they are split into the junction table booking_seats.
  • 2NF: Meets 1NF and contains NO partial dependencies (all non-key attributes fully depend on the complete primary key). In booking_seats (composite PK or surrogate PK), the seat price and booking relationship strictly depend on the key.
  • 3NF: Meets 2NF and contains NO transitive dependencies (\(X \to Y\) and \(Y \to Z\)). For example, cinema city is stored in cinemas, not redundantly copied into shows or bookings. Screen information references cinema_id, maintaining referential integrity.

  • Atomicity: Ticket booking involves three tables (bookings, booking_seats, and payments). Either all three operations succeed together or, if any step fails, the entire transaction is rolled back via conn.rollback().
  • Consistency: Foreign key constraints (ON DELETE CASCADE) and unique index uk_screen_seat ensure no phantom or duplicate seats can be created on a screen.
  • Isolation: When checking seat availability, the transaction applies row-level locking: SELECT ... FOR UPDATE. This forces concurrent booking requests to wait until the lock is released or encounter an immediate conflict, preventing race conditions.
  • Durability: Managed by MySQL's InnoDB storage engine using its write-ahead Redo Log (WAL) ensuring committed transactions survive server crashes.

A View is a virtual table defined by a saved SELECT query without taking parameters (used here for vw_active_shows and vw_cinema_revenue). A Stored Procedure encapsulates business logic, takes IN and OUT parameters, can execute multiple queries, control transactions (COMMIT/ROLLBACK), and is precompiled inside the MySQL database server for maximum performance.

A Trigger is a special stored program that executes automatically in response to specific events (INSERT, UPDATE, DELETE) on a table. In our system:
  • trg_after_booking_insert logs newly confirmed ticket reservations directly into the audit_logs table.
  • trg_after_booking_update monitors booking cancellations and automatically triggers payment status update to REFUNDED in the payments table.
